AI engineer in Gurugram. I build agentic LLM systems that run against real enterprise data — ERPs, EHRs, product catalogs — and the retrieval, governance and infrastructure underneath them. Currently at Programming.com, where I've shipped four production Generative AI systems in a year: enterprise, healthcare and ecommerce agents plus internal QA tooling.


## What I work on
Agents over systems of record. Most LLM demos query a vector store. The harder problem is putting an agent in front of an ERP or an EHR, where access has to be scoped per role, tool contracts have to survive schema changes, and a wrong answer has consequences. I built a custom MCP (Model Context Protocol) server from scratch over Epicor ERP, and a healthcare agent answering across patient documents in S3 and structured clinical records from athenahealth.
Retrieval as an engineering problem, not a prompting one. Recall can look fine while groundedness quietly fails. Chunking, hybrid search and reranking move answer quality more than prompt rewrites do.
Agents that are boring in production. Multi-agent orchestration only pays off if you can trace what happened when it broke — so explicit state graphs over autonomous delegation, and guardrails and RBAC as design constraints rather than output filters.
The whole path to production. Docker, CI/CD across AWS and Azure, Nginx, zero-downtime deploys. I'd rather understand the deploy than hand it off.
